# Document Control

## Change process
1. Create a documentation branch.
2. Update version/status and revision history.
3. Identify affected requirement, screen, API, DB object, test and ADR IDs.
4. Obtain review from impacted owners.
5. Merge only after required approvals.

## Standard header
```markdown
# Document Title
- Document ID: DOC-XXX
- Version: 1.0
- Status: Draft / In Review / Approved / Deprecated
- Owner:
- Reviewers:
- Created / Updated:
- Related documents:
- Requirement IDs:

## Purpose
## Scope
## Specification
## Validation
## Acceptance criteria
## Dependencies and risks
## Open questions
## Revision history
```

A draft or generated document is not an approval. Record who approved it and when.
